# Utility Meter Bot

Telegram-бот и Mini App для учёта коммунальных показаний. Локальное
распознавание фотографий работает на CPU через PaddleOCR: бот показывает
найденное значение и расчёт, но сохраняет его как подтверждённое только после
решения пользователя.

## Возможности

- главное меню и команды `/start`, `/help`, `/cancel`;
- создание и просмотр квартир/домов;
- добавление счётчиков холодной воды, горячей воды и электричества;
- настройка простого тарифа для ресурса, включая водоотведение;
- расчёт водоотведения как суммы расходов холодной и горячей воды по объекту;
- передача показаний фотографией или вручную;
- OpenCV-предобработка и CPU-инференс мобильными моделями PP-OCRv5;
- эвристический выбор показания с учётом confidence, предыдущего значения,
  допустимого прироста и серийного номера;
- автоматическое определение счётчика по серийному номеру на фото;
- предложение и ручной выбор счётчика по прошлым показаниям, если серийный
  номер не распознан;
- привязка найденного серийного номера к счётчику после подтверждения первого
  показания;
- передача всех фотографий одним Telegram-альбомом, когда номера привязаны ко
  всем активным счётчикам объекта;
- подтверждение, исправление или отклонение результата OCR;
- автоматическое сохранение исправлений пользователя как OCR-разметки;
- индивидуальный профиль механической панели для конкретного счётчика;
- регрессионная проверка исправленных фото перед глобальным обновлением OCR;
- раздельное хранение `ocr_value` и `confirmed_value`;
- `Decimal`-расчёт расхода и стоимости;
- предупреждение и отдельное подтверждение аномально большого прироста;
- последние подтверждённые показания по каждому счётчику;
- атомарное сохранение показания, расчётного периода и начисления в PostgreSQL;
- адаптивный Telegram Mini App со сводкой по объектам, счётчикам, последним
  показаниям и расходу;
- добавление и безопасное удаление объектов и счётчиков из Mini App.

## Архитектура

Зависимости направлены от Telegram transport к application services и далее к
абстракциям репозиториев. Supabase SDK используется только в
`src/infrastructure/supabase`.

```text
Telegram / aiogram + authenticated Mini App / aiohttp
                         ↓
Application services / OCR executor (`asyncio.to_thread`)
        ↓
Repository and storage protocols
        ↓
Supabase Data API / Storage + local PaddleOCR/OpenCV
```

Идентификаторы сущностей — UUID, показания и деньги — `Decimal`/PostgreSQL
`NUMERIC`. Каждый пользовательский запрос к дочерней сущности проходит ownership
проверку по цепочке `users → properties → meters → readings`.

## Настройка Supabase

1. Создайте проект Supabase.
2. Выполните SQL-файлы из `supabase/migrations` по порядку через SQL Editor или
   Supabase CLI.
3. Скопируйте `.env.example` в `.env` и заполните `BOT_TOKEN`, `SUPABASE_URL` и
   `SUPABASE_SERVICE_ROLE_KEY`.

Service Role Key предназначен только для backend-контейнера. Не отправляйте его
в Telegram и не добавляйте `.env` в систему контроля версий. Таблицы создаются с
включённым RLS без публичных политик; private bucket `meter-photos` доступен
backend через service role.

Если файлы `001`–`007` уже применены, последовательно выполните
[`008_ocr_serial_feedback.sql`](supabase/migrations/008_ocr_serial_feedback.sql)
и [`009_meter_deletion.sql`](supabase/migrations/009_meter_deletion.sql).
Миграции `007` и `008` добавляют закрытые от публичного API таблицы размеченных
OCR-ошибок, индивидуальные профили счётчиков и отдельное хранение исправленного
серийного номера. Миграция `009` разрешает корректное каскадное удаление
счётчика вместе с относящимися к нему начислениями.

## Telegram Mini App

Mini App показывает количество объектов и счётчиков, статус передачи показаний
за текущий месяц, два последних значения и вычисленный расход. В нём можно
добавлять объекты и счётчики, а также удалять их после явного подтверждения.
Удаление необратимо: вместе со счётчиком удаляются его показания и начисления,
а вместе с объектом — все его счётчики. Связанные оригиналы фото удаляются из
private Storage; сбой очистки Storage записывается в лог и показывается в
интерфейсе, не скрывая уже выполненное удаление из базы.

API не принимает Telegram ID от браузера. Каждый запрос подписан исходной
строкой `Telegram.WebApp.initData`; backend проверяет её HMAC с токеном бота и
срок действия, после чего все операции дополнительно проходят ownership-проверки.
Service Role Key остаётся только внутри backend-контейнера.

Для публикации нужен домен с действующим HTTPS-сертификатом. Рекомендуется
выделить Mini App отдельный поддомен и проксировать его целиком на локальный
порт приложения — так одновременно доступны страница `/miniapp/` и API
`/api/v1/`. Пример конфигурации находится в
[`deploy/nginx-miniapp.conf.example`](deploy/nginx-miniapp.conf.example).

1. Направьте DNS-запись выбранного поддомена на сервер и выпустите для него
   TLS-сертификат.
2. Установите Nginx-конфигурацию из примера, заменив домен и пути сертификата.
3. Добавьте в `.env` публичный адрес и порт:

   ```dotenv
   MINI_APP_URL=https://meters.example.com/miniapp/
   MINI_APP_HOST=0.0.0.0
   MINI_APP_PORT=8080
   ```

4. Выполните `docker compose up --build -d` и проверьте
   `https://meters.example.com/healthz`.

После перезапуска бот установит системную кнопку меню «Дашборд», добавит команду
`/app` и покажет кнопку Mini App в ответе на `/start`. Если `MINI_APP_URL`
оставлен пустым, встроенный HTTP-сервер и кнопки Mini App не включаются. Compose
публикует его порт только на `127.0.0.1`, поэтому доступ снаружи идёт через
HTTPS-прокси.

## Локальный запуск

```bash
python3 -m venv .venv
.venv/bin/python -m pip install paddlepaddle==3.0.0 \
  --index-url https://www.paddlepaddle.org.cn/packages/stable/cpu/
.venv/bin/python -m pip install -e '.[dev,ocr]'
.venv/bin/ruff check src tests
.venv/bin/mypy src
.venv/bin/python -m pytest -q
.venv/bin/python -m src.main
```

## Первый пользовательский сценарий

1. Отправьте боту `/start`.
2. Откройте «Объекты» и добавьте квартиру или дом.
3. Добавьте объекту один или несколько счётчиков.
4. В разделе «Тарифы» задайте цены ресурсов и отдельный тариф водоотведения.
5. Откройте «Передать показания». Можно выбрать счётчик заранее или нажать
   «Определить счётчик по фото».
6. Сделайте прямой снимок дисплея без бликов и отправьте его как изображение.
7. Если серийный номер не найден, выберите предложенный по прошлым показаниям
   счётчик либо другой счётчик из списка.
8. Проверьте распознанное значение, расход и стоимость, затем подтвердите или
   исправьте показание.
9. Первое подтверждённое значение станет базовым; следующее создаст расход и
   начисление за текущий месяц.

После подтверждения первой фотографии распознанный серийный номер сохраняется у
счётчика, если номер ещё не был задан. Когда номера есть у всех активных
счётчиков объекта, в меню передачи показаний появляется кнопка «Отправить все
фото одним альбомом». Выберите ровно по одной фотографии каждого счётчика и
отправьте их одним Telegram-альбомом — порядок фотографий не важен.

Оригинал загружается в private bucket только после успешного распознавания и
валидации. Неудачный OCR не создаёт запись и предлагает повторить фото либо
перейти к ручному вводу. Аномально большой прирост явно помечается в
предпросмотре.

Если OCR показал неверные данные, нажмите «Исправить»: сначала введите
фактическое показание, затем правильный серийный номер или оставьте распознанный.
Бот сохранит исходный результат, оба исправленных значения, распознанный текст и
путь к оригинальному фото. Явно исправленный номер будет привязан к выбранному
счётчику даже вместо ранее ошибочно сохранённого номера, но не сможет дублировать
номер другого счётчика объекта. Если цифры барабанов распознаны верно, но
ошибочно выбрана дробная часть, бот сразу создаст профиль только для выбранного
счётчика. При ошибке самих цифр или номера пример останется в очереди на
доработку общего детектора и не изменит поведение для других пользователей.

Перед глобальным изменением OCR запустите регрессию по всем пользовательским
исправлениям. Команда вернёт ненулевой код, пока хотя бы один сохранённый пример
распознаётся не так, как указал пользователь:

```bash
docker compose run --build --rm app python -m src.tools.ocr_feedback_regression
```

После отчёта с `"safe_to_deploy": true` обновление можно развернуть обычной
командой `docker compose up --build -d`.

Основные OCR-настройки находятся в `.env.example`: число CPU-потоков, лимит
размера файла, максимальное разрешение, grayscale, усиление контраста,
бинаризация и коррекция перспективы. Для Raspberry Pi безопасные значения по
умолчанию — `OCR_CPU_THREADS=2` и `OCR_MAX_CONCURRENCY=1`.

Для ручной диагностики отправьте `/ocr_debug`, затем пришлите снимок и текстом
опишите ожидаемые значения. Бот
вернёт ID образца. Сравнить последний образец на цветной, серой, контрастной и
бинаризованной предобработке можно внутри контейнера:

```bash
docker compose exec app python -m src.tools.ocr_debug
```

Для конкретного образца добавьте его UUID в конец команды. Фото и метаданные
хранятся только в локальном Docker volume `ocr_debug`.

## Docker Compose

```bash
docker compose up --build -d
docker compose logs -f app
```

Compose запускает только application container; PostgreSQL локально не
поднимается. CPU wheel `paddlepaddle==3.0.0` устанавливается из официального
индекса, где подтверждена сборка ARM64 для Python 3.12. Volume `paddle_models`
хранит мобильные модели между перезапусками. При первом фото модели скачиваются
один раз, последующие запуски используют кэш.
