# Utility Meter Bot

MVP Telegram-бота для учёта коммунальных показаний. Этап 3 добавляет локальное
распознавание фотографий на CPU через PaddleOCR: бот показывает найденное
значение и расчёт, но сохраняет его как подтверждённое только после решения
пользователя.

## Возможности

- главное меню и команды `/start`, `/help`, `/cancel`;
- создание и просмотр квартир/домов;
- добавление счётчиков холодной воды, горячей воды и электричества;
- настройка простого тарифа для объекта и типа ресурса;
- передача показаний фотографией или вручную;
- OpenCV-предобработка и CPU-инференс мобильными моделями PP-OCRv5;
- эвристический выбор показания с учётом confidence, предыдущего значения,
  допустимого прироста и серийного номера;
- подтверждение, исправление или отклонение результата OCR;
- раздельное хранение `ocr_value` и `confirmed_value`;
- `Decimal`-расчёт расхода и стоимости;
- предупреждение и отдельное подтверждение аномально большого прироста;
- последние подтверждённые показания по каждому счётчику;
- атомарное сохранение показания, расчётного периода и начисления в PostgreSQL.

## Архитектура

Зависимости направлены от Telegram transport к application services и далее к
абстракциям репозиториев. Supabase SDK используется только в
`src/infrastructure/supabase`.

```text
Telegram / aiogram
        ↓
Application services / OCR executor (`asyncio.to_thread`)
        ↓
Repository and storage protocols
        ↓
Supabase Data API / Storage + local PaddleOCR/OpenCV
```

Идентификаторы сущностей — UUID, показания и деньги — `Decimal`/PostgreSQL
`NUMERIC`. Каждый пользовательский запрос к дочерней сущности проходит ownership
проверку по цепочке `users → properties → meters → readings`.

## Настройка Supabase

1. Создайте проект Supabase.
2. Выполните SQL-файлы из `supabase/migrations` по порядку через SQL Editor или
   Supabase CLI.
3. Скопируйте `.env.example` в `.env` и заполните `BOT_TOKEN`, `SUPABASE_URL` и
   `SUPABASE_SERVICE_ROLE_KEY`.

Service Role Key предназначен только для backend-контейнера. Не отправляйте его
в Telegram и не добавляйте `.env` в систему контроля версий. Таблицы создаются с
включённым RLS без публичных политик; private bucket `meter-photos` доступен
backend через service role.

Если файлы `001`–`004` уже применены на предыдущем этапе, выполните только
[`005_confirm_recognized_reading.sql`](supabase/migrations/005_confirm_recognized_reading.sql).
Функция из этой миграции атомарно подтверждает OCR-показание и обновляет
начисление, а также защищает от повторного подтверждения.

## Локальный запуск

```bash
python3 -m venv .venv
.venv/bin/python -m pip install paddlepaddle==3.0.0 \
  --index-url https://www.paddlepaddle.org.cn/packages/stable/cpu/
.venv/bin/python -m pip install -e '.[dev,ocr]'
.venv/bin/ruff check src tests
.venv/bin/mypy src
.venv/bin/python -m pytest -q
.venv/bin/python -m src.main
```

## Первый пользовательский сценарий

1. Отправьте боту `/start`.
2. Откройте «Объекты» и добавьте квартиру или дом.
3. Добавьте объекту один или несколько счётчиков.
4. В разделе «Тарифы» задайте цену соответствующего ресурса.
5. Откройте «Передать показания», выберите счётчик и способ «Отправить фото».
6. Сделайте прямой снимок дисплея без бликов и отправьте его как изображение.
7. Проверьте распознанное значение, расход и стоимость, затем подтвердите или
   исправьте показание.
8. Первое подтверждённое значение станет базовым; следующее создаст расход и
   начисление за текущий месяц.

Оригинал загружается в private bucket только после успешного распознавания и
валидации. Неудачный OCR не создаёт запись и предлагает повторить фото либо
перейти к ручному вводу. Аномально большой прирост явно помечается в
предпросмотре.

Основные OCR-настройки находятся в `.env.example`: число CPU-потоков, лимит
размера файла, максимальное разрешение, grayscale, усиление контраста,
бинаризация и коррекция перспективы. Для Raspberry Pi безопасные значения по
умолчанию — `OCR_CPU_THREADS=2` и `OCR_MAX_CONCURRENCY=1`.

## Docker Compose

```bash
docker compose up --build -d
docker compose logs -f app
```

Compose запускает только application container; PostgreSQL локально не
поднимается. CPU wheel `paddlepaddle==3.0.0` устанавливается из официального
индекса, где подтверждена сборка ARM64 для Python 3.12. Volume `paddle_models`
хранит мобильные модели между перезапусками. При первом фото модели скачиваются
один раз, последующие запуски используют кэш.
